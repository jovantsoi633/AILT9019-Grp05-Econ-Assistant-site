AILT9019 · Group 5 · Introductory economics

Answers you can check against the textbook

A local study assistant for first-year economics students. It answers concept questions only from passages of Principles of Economics 2e (Chapters 3 and 5), shows the passage behind every claim, and says so when the textbook does not cover a question.

GitHub repository How to run it

The repository is private and shared with the AILT9019 teaching team.

Who it is for and what it solves

Users

First-year students reading or revising an introductory economics course: for example, someone who knows the definitions of demand and quantity demanded but is unsure which one applies when a price changes.

Problem

A general chatbot can explain a concept, but a student cannot easily see where the explanation comes from or whether the course textbook says the same. Finding the right section by hand takes time.

Not for

  • investment or personal financial advice
  • market predictions
  • writing or grading assignments
  • topics outside economics, or chapters not included

How it works: input → processing → output

What we built, and what we used

Built by the team

  • A 267-passage corpus taken verbatim from the CC BY 4.0 PDF, with chapter, section, PDF and printed page, and attribution
  • BM25 index, chapter filter and relevance rule (τ set on development questions)
  • Local personal-information check; fixed refusal and evidence messages
  • Prompts, citation checking, the step-by-step trace and the interface
  • Evaluation runner, frozen 21-question test set, baseline and review tools

Existing tools we rely on

  • DeepSeek API (deepseek-flash): request classification, query rewriting and answer wording
  • Streamlit: web interface framework
  • openai Python package: an API client (we do not use OpenAI models)
  • BM25: a standard ranking formula; we implemented it, but did not invent it
  • OpenStax textbook content (CC BY 4.0)

Economics-specific customisation

Students need to check a definition against the course text, so the system answers only from retrieved textbook passages and refuses unsupported answers. Comparison questions such as “shift vs movement along the demand curve” are handled with paired evidence. Refusals target what a revising student might ask that the textbook cannot support: investment choices, price forecasts and graded work.

Evaluation results

A 21-question test set (15 in-scope, 3 not covered by the chapters, 3 requests to refuse) plus 3 synthetic personal-data inputs was written separately from the development questions, frozen, and run once on 2026-11-14. The test set used 39 API requests in total.

Targets were set in the proposal before testing. Answer quality was scored independently by two team members; they agreed on 15 of 15 items. Failures: T05 (correct citations, but the answer left out what shifts the demand curve) and T06 (not answered).

Compared with using the same model directly

We asked the same 21 questions to the same model with no system prompt and no textbook passages. It answered all 21, including the 3 questions our chapters do not cover, with no note about scope. Its explanations were mostly correct, but none of the 21 named a source a student could check, and it declined none of the 3 requests we refuse: it ended the investment question with “the fixed deposit is the safer fit”, gave a flat-price forecast, and offered to write “submission-ready answers”. (Scored by the same two reviewers.) 6 of its answers hit the same 600-token limit.

Failure case: an in-scope question that went unanswered

“How is consumer surplus different from producer surplus?”

Expected: a cited answer from the consumer- and producer-surplus definitions.
Observed: the query consumer surplus versus producer surplus difference retrieved ch3-118 (11.77), ch3-122 (11.51), ch3-121 (11.34). These passages discuss price controls and mention both terms many times. The definitions ranked 5th and 6th. The answer model replied that the evidence was insufficient, so the student saw “not enough evidence”. Nothing was invented, but the question was not answered.
Next step: retrieve per concept, or more passages, for comparison questions, and test this on new development questions.

Boundary case: what really stopped the uncovered questions

The relevance threshold stopped 0 of 3 uncovered questions; the answer model’s “insufficient evidence” reply stopped 3. General words (“economist”, “pricing”, “rise”) gave BM25 scores above τ. On this corpus the second safeguard does the real work, and it depends on model behaviour.

Limitations

  • Only Chapters 3 (Demand and Supply) and 5 (Elasticity) are included.
  • Keyword retrieval misses passages worded differently from the question; top 3 can be too narrow.
  • The privacy check catches obvious formats (email, phone, student ID, HKID) only, not names or other details.
  • Model output varies between runs even at temperature 0. Citations let you check an answer; they do not prove it is correct.
  • 15 in-scope test questions are a small sample: one question changes a rate by about 7 percentage points.

Run it on your computer

The app runs locally; it is not hosted on this page. Textbook search needs no key. AI answers need your own DeepSeek API key, entered in a masked field and kept only in the browser session.

Cloning requires repository access (granted to the teaching team).

git clone https://github.com/jovantsoi633/AILT9019-Grp05-Econ-Assistant.git
cd AILT9019-Grp05-Econ-Assistant
python -m pip install -r requirements.txt
python -m pytest -q          # offline tests: 76 passed in 4.36s
python -m streamlit run app.py
